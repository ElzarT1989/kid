# KidsEdu AI — Персональная образовательная видео-платформа с ИИ-куратором

`SPEC.md` / `CLAUDE.md` — полная техническая спецификация проекта.

> Эта версия спеки обновлена с учётом архитектурных правок, принятых в
> процессе разработки Этапа 1 (см. раздел 8 «Отличия от исходной версии
> спеки» и `CLAUDE.md`).

## 1. Концепция и цель проекта

KidsEdu AI — это автономная экосистема фильтрации, планирования и
воспроизведения образовательного видеоконтента для детских профилей
(возраст: 2 года и 5 лет), разворачиваемая на выделенных смартфонах Samsung
Galaxy S20+ в защищённом режиме киоска (Kiosk Mode).

Ключевые задачи системы:

- **Абсолютная изоляция от алгоритмов рекомендаций**: полное исключение
  реакций YouTube, VK Видео, дофаминового мусора (шортсы, распаковки,
  громкий треш-контент, скрытая реклама).
- **Детерминированный годовой учебный план**: автоматический отбор
  видеоконтента на основе педагогических программ для дошкольников с
  динамической адаптацией под успеваемость.
- **Геймифицированный дофаминовый ограничитель**: обязательные
  интерактивные микро-квизы с голосовым сопровождением между роликами,
  блокирующие непрерывное бессознательное потребление.
- **Прозрачность для родителей**: веб-панель мониторинга и Telegram-бот
  для управления расписанием, просмотра аналитики и оперативной
  корректировки тем.

## 2. Целевая аудитория и профилизация

| Параметр | Профиль «Младшая» (2 года) | Профиль «Старшая» (5 лет) |
|---|---|---|
| Образовательный фокус | Базовые цвета, геометрия, звуки природы/животных, развитие речи, крупная моторика, эмоциональный интеллект. | Чтение/фонетика, счёт и логика, устройство окружающего мира, основы космоса и физики, английский язык A0, социализация. |
| Длительность сессии | 10–15 минут (1–2 коротких видео по 3–5 мин). | 20–30 минут (2–3 видео по 7–10 мин). |
| Формат микро-тестов | Голосовой вопрос (TTS) + выбор из 2 крупных визуальных карточек (без текста). | Голосовой + текстовый вопрос + выбор из 3–4 иллюстрированных карточек. |
| Интерфейс плеера | Сверхкрупные элементы (≥120px), отсутствие мелких текстовых кнопок. | Крупные элементы, цветовая индикация прогресса темы недели. |
| Лимит времени | До 30 минут в день. | До 60 минут в день. |

## 3. Технический стек и инфраструктура

Система строится исключительно на бесплатных, открытых и self-hosted
решениях для обеспечения полной автономности.

**Backend & Core Services**

- Среда выполнения: Docker Compose (Railway в проде; Windows 11 + WSL2
  Ubuntu 22.04 LTS для локальной разработки).
- Язык разработки: Python 3.11.
- Веб-фреймворк: FastAPI (асинхронный обработчик API, OpenAPI 3.0).
- Валидация данных: Pydantic v2 (строгая валидация схем и Structured
  Outputs для LLM).
- ORM & БД: SQLAlchemy 2.0 AsyncIO + PostgreSQL 16 (прод) / SQLite с WAL
  (локальная разработка).
- Парсинг и медиа: yt-dlp (извлечение субтитров .vtt/.srt, метаданных и
  скачивание одобренных видео — см. п. 8.1).
- Фоновые задачи: APScheduler (периодический парсинг, сбор статистики и
  очистка кеша).

**AI & Media Engines**

- LLM-маршрутизатор: Google Gemini API (`gemini-2.5-flash` /
  `gemini-2.5-pro`, бесплатный тир) через `google-genai` SDK для анализа
  субтитров и генерации вопросов с Pydantic Schema Enforcement.
- Визуальный слой модерации: ffmpeg (scene-detect/громкость) + выборка
  кадров через Gemini vision (см. п. 8.5).
- Синтез речи: `edge-tts` — бесплатная генерация русского текста в аудио
  MP3 через Microsoft Edge Read Aloud API.
- Бот-управление: `aiogram` 3.x (Telegram Bot API).

**Frontend & Device Control**

- Детский плеер & Admin UI: React 18 / Vite, TailwindCSS, Lucide-Icons.
  PWA адаптация под разрешение экрана Samsung Galaxy S20+ (3200×1440 /
  viewport ~800×360px).
- Защита устройства: Fully Kiosk Browser (Android app) — режим блокировки
  выхода, скрытие системных баров, запрет вызова настроек, автозапуск PWA.

### Модуль 1 — Контент-парсер и ИИ-модератор (`app/services/ingestor.py` & `moderator.py`)

1. **Белый список каналов**: `ChannelSource` — таблица БД (не
   конфиг-файл), управляемая через Telegram-бота (`/add_channel`,
   `/list_channels`).
2. **Сбор и экстракция**: фоновый воркер через yt-dlp каждые
   `INGESTOR_INTERVAL_HOURS` часов запрашивает свежие ролики, извлекает
   текстовые субтитры и метаданные.
3. **Двухслойный ИИ-фильтр**:
   - Текстовый слой: субтитры отправляются в Gemini 2.5 Flash с
     требованием строгого ответа по JSON-схеме
     (`VideoModerationResultSchema`).
   - Визуальный слой: ffmpeg-выборка кадров + Gemini vision
     (`VisualModerationResultSchema`) — субтитров недостаточно для отлова
     агрессивного монтажа, криков и мигающих эффектов без текстового
     следа.
   - Видео одобряется (`is_approved=True`) только если оба слоя дали
     положительный вердикт.
4. **Критерии отклонения контента**:
   - Наличие резких вскриков, визгов, агрессивных звуковых эффектов.
   - Контент типа «Unboxing», реклама игрушек, демонстрация сладостей.
   - Быстрая смена кадров (клиповый монтаж < 1.5 сек на кадр).
   - Отсутствие явной образовательной цели.
5. **Локальное скачивание**: при одобрении видео скачивается локально в
   `VIDEO_STORAGE_PATH` (`VideoItem.local_video_path`) — см. п. 8.1.
6. **Генерация вопросов**: при одобрении ролика LLM автоматически
   генерирует 2 проверочных квиза с привязкой к таймкоду конца видео.

### Модуль 2 — Генератор годового учебного плана (`app/services/curriculum.py`)

1. **Иерархия плана**: Годовой план → Модуль (месяц) → Тема (неделя) →
   Дневной плейлист (1–3 видео), персистентно хранимый в
   `DailyPlaylist`/`DailyPlaylistItem` (см. п. 8.3).
2. **Динамическая сложность**:
   - При результатах квизов ≥80% успеха за неделю система повышает
     сложность темы или переводит на следующий модуль.
   - При результатах ≤50% успеха система подбирает
     дублирующие/закрепляющие ролики по той же теме с другим визуальным
     рядом.

### Модуль 3 — Защищённый плеер и движок квизов (`frontend/src/pages/ChildPlayer.tsx`)

1. **Изоляция видеоплеера**: HTML5 / YouTube IFrame API с атрибутами
   `controls=0`, `rel=0`, `disablekb=1`. Поверх iframe накладывается
   прозрачный блок, перехватывающий клики, исключая переход на внешние
   сайты.
2. **Квиз-пауза**: по завершении ролика видео скрывается, включается
   компонент `QuizOverlay.tsx`.
3. **Озвучка через TTS**: сервис `tts.py` заранее синтезирует .mp3 файл
   вопроса через `edge-tts`. Плеер проигрывает его при открытии квиза.
4. **Геймифицированная обратная связь**: при правильном ответе
   проигрывается мягкий анимационный эффект и начисляются звёздочки. При
   ошибке подсвечивается верный вариант без негативных штрафов.

### Модуль 4 — Родительский контроль и аналитика (`app/bot/` & `frontend/src/pages/ParentAdmin.tsx`)

1. **Дашборд**: просмотр общего времени просмотра, списка изученных
   навыков, точности ответов на квизы.
2. **Telegram-управление**:
   - `/status` — текущий статус профилей и время просмотра за сегодня.
   - `/add_channel <platform> <id> [возраст] [название]` — добавить канал
     в белый список.
   - `/list_channels` — список одобренных каналов.
   - `/add_topic <тема>` — принудительно добавить тему в план текущей
     недели (например, «гигиена зубов»).
   - `/block_video <id>` — моментально исключить ролик из базы.

## 5. Схема базы данных

ORM: SQLAlchemy 2.0 Async, `backend/app/models/database.py`. 8 таблиц:

- `ChildProfile` — детский профиль (имя, возраст, дневной лимит минут).
- `ChannelSource` — белый список каналов/плейлистов (см. п. 8.2).
- `CurriculumNode` — узел учебного плана (месяц/неделя/тема/навыки/статус).
- `VideoItem` — видео (метаданные, субтитры, оценка, `local_video_path`
  вместо кэша живых ссылок — см. п. 8.1).
- `QuizQuestion` — квиз-вопрос, привязанный к видео.
- `DailyPlaylist` / `DailyPlaylistItem` — персистентный дневной плейлист
  (см. п. 8.3).
- `WatchLog` — лог просмотра (`watched_seconds`, `completed`, `skipped`,
  `quiz_passed`, `attempts_count` — см. п. 8.4).

Полные определения — в `backend/app/models/database.py`.

Pydantic-схемы для LLM и API — в `backend/app/schemas/moderation.py`
(`VideoModerationResultSchema`, `GeneratedQuizSchema`,
`VisualModerationResultSchema`) и `backend/app/schemas/admin.py`.

## 7. Пошаговый план разработки (Roadmap)

> Порядок этапов переопределён относительно исходной версии спеки — см.
> п. 8.6.

**Этап 0 — Физическая изоляция (вне репозитория, приоритет)**
Fully Kiosk Browser + минимальный статический плейлист на телефонах —
самый быстрый способ немедленно остановить утечку детей в
треш-контент, параллельно с разработкой Этапа 2.

**Этап 1 — Инфраструктура и ядро БД (MVP Core)** — ✅ реализовано
1. Настройка окружения: Python 3.11, FastAPI, SQLAlchemy 2.0 Async.
2. Создание структуры таблиц БД (8 таблиц, `create_all` при старте).
3. Базовые CRUD-эндпоинты для `ChildProfile` и `ChannelSource`.
4. Рабочие команды Telegram-бота: `/status`, `/add_channel`,
   `/list_channels`, `/block_video`.

**Этап 2 — Контент-пайплайн и ИИ-модерация** — ✅ реализовано
1. `app/services/ingestor.py`: интеграция yt-dlp, локальное скачивание
   одобренных видео (с `movflags=faststart`, см. Этап 3).
2. `app/services/moderator.py`: Gemini API со строгим выходом
   (`VideoModerationResultSchema`) + визуальный слой (ffmpeg + vision).
3. `app/services/tts.py`: генерация .mp3 файлов вопросов через edge-tts.

**Этап 3 — Детский Киоск-плеер (Frontend)** — ✅ реализовано
1. React 19 + Vite + Tailwind v4 PWA (`frontend/`).
2. `ProfileSelect.tsx` (огромные тач-аватары), `VideoPlayer.tsx`
   (HTML5 `<video>` на локальный файл вместо YouTube IFrame — см. п. 8.1;
   прозрачный оверлей + tap-to-start fallback при заблокированном
   автоплее), `QuizOverlay.tsx` (авто-TTS, крупные карточки, подсветка
   верного варианта без штрафа за ошибку), `ChildPlayer.tsx` (полный
   цикл видео → квиз(ы) → `POST /player/{id}/watch-log` → следующий
   ролик).
3. Backend дополнен под нужды плеера: `video_url`/`audio_url` вместо
   сырых путей, `GET /player/videos/{id}/quizzes`,
   `POST /player/{child_id}/watch-log`, статик-раздача `/media/videos` и
   `/media/tts`.

   При E2E-проверке (Playwright) найдены и исправлены два реальных
   бага: (1) `get_today_playlist` падал с `MissingGreenlet` из-за
   ленивой загрузки `item.video` без `selectinload` в асинхронной
   сессии; (2) видео, скачанные `ingestor.download_video_file` без
   `movflags=faststart`, не проигрывались браузером прогрессивно (moov
   atom в конце файла) — добавлен `postprocessor_args` в yt-dlp.

**Этап 4 — Генератор учебного плана и логика адаптации** — ✅ реализовано
1. `curriculum_data.py`: фиксированный годовой план — 12 модулей × 4
   темы на возрастной профиль (2 и 5 лет), закольцован на 48 недель.
2. `curriculum.py`: `ensure_current_node` создаёт первый узел плана и
   лениво продвигает его при следующем обращении после того, как под
   текущим узлом накопилось 7 дневных плейлистов (устойчиво к
   пропущенным дням, а не завязано на календарь):
   - успех ≥80% → узел `MASTERED`, переход к следующей теме;
   - успех ≤50% → узел `NEEDS_REVIEW`, та же тема повторяется на других
     видео (уже показанные ролики не исключаются жёстко, а лишь
     оттесняются в конец списка кандидатов — плейлист всегда
     заполняется до целевого числа видео, если в базе вообще есть
     подходящий по возрасту одобренный контент).
   - `build_daily_playlist` — идемпотентная точка входа, подключена в
     `GET /player/{child_id}/today` (Этап 1 STUB закрыт): при отсутствии
     плейлиста на сегодня генерирует его через curriculum engine вместо
     404.

   Проверено smoke-тестом (in-memory SQLite + реальный HTTP API):
   генерация первой недели, идемпотентность, переход при 100% успехе,
   повтор темы при провале с гарантированно другими видео, соблюдение
   дневного лимита минут.

**Этап 5 — Telegram-бот (расширение) и деплой в Kiosk Mode**
1. Расширение бота (webapp, отчёты).
2. Docker Compose / Railway для продакшена.
3. Настройка Fully Kiosk Browser на устройствах.

## 8. Отличия от исходной версии спеки

Архитектурные решения, принятые в процессе разработки и отличающиеся от
первоначального PDF-документа:

1. **Локальное скачивание видео вместо кэша "живых" ссылок.**
   HLS/MP4 ссылки протухают за часы, а между модерацией и показом по
   плану может пройти недели — поэтому `VideoItem.local_video_path`
   заменяет `stream_url_cache`.
2. **`ChannelSource` — таблица БД**, управляемая через Telegram-бота, а
   не статический конфиг-файл.
3. **`DailyPlaylist`/`DailyPlaylistItem`** — персистентная сущность, а
   не пересчёт "на лету" из `CurriculumNode` при каждом запросе плеера.
4. **`WatchLog.completed`/`skipped`** — фиксируются отдельно от
   `watched_seconds`, чтобы отличать полный просмотр от прерванного.
5. **Двухслойная модерация**: текстовый анализ субтитров недостаточен —
   добавлен визуальный слой (ffmpeg scene-detect/громкость + выборка
   кадров через Gemini vision), прежде чем `moderator.py` становится
   единственным гейткипером.
6. **Порядок разработки переопределён**: сначала физическая изоляция от
   YouTube/VK-приложений (Этап 0, вне репозитория — Fully Kiosk Browser +
   статический плейлист), затем backend-скелет, затем автоматизация.
7. **Монетизация/масштабирование на чужих детей** — сознательно вне
   скоупа до минимум месяца стабильной работы на своих детях
   (юридический вес: 152-ФЗ, права на видео).
